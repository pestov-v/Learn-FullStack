Пояснення для п'ятирічного

Уяви ляльку-робота. HTML — це її скелет: голова, руки, ноги, і що до чого прикріплено. Без скелета — просто купка деталей на підлозі. CSS — це одяг і макіяж: якого кольору сукня, чи великий капелюх, чи стоять руки в боки. Один скелет можна одягнути тисячею способів. JavaScript — це мозок: коли натиснути на ніс — робот моргає, коли сказати «привіт» — махає рукою. Браузер збирає всі три частини разом і показує тобі живу сторінку. А ще робот уміє дзвонити на кухню (сервер) і просити нові дані — це fetch.

1. Три мови — одна сторінка

У розділі 01 ми побачили, що сервер надсилає браузеру HTML, а браузер будує з нього DOM і малює пікселі. Тепер подивимось на ці три складові з боку того, хто їх пише. Головний принцип — розділення відповідальностей (separation of concerns): кожна мова робить одну справу і не лізе в чужу.

  • HTML (HyperText Markup Language) описує що на сторінці: заголовок, абзац, список, кнопка, картинка. Це не мова програмування — там немає умов і циклів. Це мова розмітки.
  • CSS (Cascading Style Sheets) описує, як це виглядає: колір, розмір, розташування, анімація.
  • JavaScript описує, що відбувається: натиснули — з'явилось, ввели — перевірилось, минула секунда — оновилось.

Мінімальна сторінка, яка підключає всі три частини:

<!doctype html>
<html lang="uk">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Мій перший сайт</title>
  <link rel="stylesheet" href="style.css">   <!-- одяг -->
</head>
<body>
  <h1>Привіт, світе!</h1>                   <!-- скелет -->
  <button id="btn">Натисни</button>
  <script src="app.js" defer></script>      <!-- мозок -->
</body>
</html>

Зверніть увагу на defer у скрипта: як ми з'ясували в розділі 01, без нього браузер зупинить парсинг HTML, щоб виконати скрипт, і document.getElementById("btn") поверне null, бо кнопки ще не існує.

2. HTML: скелет

Теги, елементи, атрибути

HTML складається з елементів (elements). Елемент — це відкривальний тег (tag), вміст і закривальний тег: <p>Текст</p>. Деякі елементи порожні і не мають закривального тега: <img>, <br>, <input>. Тег може мати атрибути (attributes) — додаткові налаштування у вигляді ім'я="значення":

<a href="https://example.com" target="_blank" rel="noopener">Посилання</a>
<img src="cat.jpg" alt="Рудий кіт спить на клавіатурі" width="300">
<input type="email" name="email" placeholder="you@example.com" required>

Атрибут alt у картинки — не декорація: його читає скрінрідер для незрячих і показує браузер, якщо картинка не завантажилась. Атрибут id — унікальний ідентифікатор елемента на сторінці, class — «ярлик», який можна повісити на багато елементів одразу; за ними CSS і JS знаходять потрібні елементи.

Семантика: називай речі своїми іменами

Можна зробити всю сторінку з <div> — і вона працюватиме. Але браузер, пошуковик і скрінрідер не зрозуміють, де шапка, а де основний зміст. Семантичні теги (semantic tags) кажуть, що це за частина:

ТегЩо означає
<header>Шапка сторінки або секції: логотип, назва
<nav>Навігація: меню, посилання
<main>Основний зміст — рівно один на сторінку
<article>Самодостатній блок: стаття, пост, картка товару
<section>Тематична секція, зазвичай із заголовком
<aside>Побічне: бічна панель, примітка
<footer>Підвал: контакти, копірайт
<h1>…<h6>Заголовки за рівнями; h1 — один на сторінку
<ul>/<ol>/<li>Список маркований / нумерований / пункт
<button>Кнопка (не <div onclick>!) — працює з клавіатури, має фокус

Форми: як користувач щось надсилає

Форма (form) — головний спосіб зібрати дані від людини. Кожне поле має name — під цим іменем значення полетить на сервер. <label for="..."> зв'язує підпис із полем: клік по підпису ставить фокус у поле, а скрінрідер читає підпис.

<form action="/api/subscribe" method="post">
  <label for="email">Ваш email</label>
  <input id="email" name="email" type="email" required>

  <label for="plan">Тариф</label>
  <select id="plan" name="plan">
    <option value="free">Безкоштовний</option>
    <option value="pro">Pro</option>
  </select>

  <label><input type="checkbox" name="agree" required> Погоджуюсь з умовами</label>

  <button type="submit">Підписатися</button>
</form>

Без JavaScript браузер сам відправить POST /api/subscribe з тілом email=...&plan=pro&agree=on і перезавантажить сторінку. Атрибут required і type="email" дають безкоштовну валідацію на клієнті — але сервер завжди перевіряє ще раз, бо клієнту довіряти не можна.

Повна сторінка

<!doctype html>
<html lang="uk">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>Блог про котів</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <header>

Чому це важливо

Семантичний HTML — це безкоштовна доступність, SEO і зрозумілий код одночасно. Кнопка <button> сама реагує на Enter і пробіл, отримує фокус із Tab і повідомляє скрінрідеру «кнопка». Щоб те саме зробив <div>, треба написати 20 рядків JS і все одно щось забути.

3. CSS: одяг

Селектори і каскад

CSS-правило = селектор (selector) (кого стилізуємо) + блок властивостей (properties):

/* за тегом */
p { line-height: 1.6; }

/* за класом — найпоширеніший спосіб */
.card { padding: 16px; border-radius: 12px; }

/* за id — унікальний елемент */
#header { position: sticky; top: 0; }

/* вкладеність: посилання всередині nav */
nav a { text-decoration: none; }

/* стан: при наведенні */
.card:hover { box-shadow: 0 4px 12px rgba(0,0,0,.1); }

/* атрибут */
input[type="email"] { border-color: blue; }

«Каскадні» в назві означає: якщо на один елемент претендують кілька правил, перемагає більш специфічне (specificity) — id сильніший за клас, клас сильніший за тег; при рівній силі — те, що написане нижче. Правило з !important ламає всю систему, тому його уникають.

Блокова модель (box model)

Кожен елемент — це прямокутна коробка з чотирьох шарів: вміст (content), внутрішній відступ (padding), рамка (border), зовнішній відступ (margin). Це як подарунок: сама річ, м'який папір навколо, коробка, і простір між коробками на полиці.

/* Робимо box model передбачуваною для всіх елементів */
*, *::before, *::after { box-sizing: border-box; }

.card {
  width: 300px;        /* з border-box це вже включає padding і border */
  padding: 16px;
  border: 2px solid #ddd;
  margin: 12px auto;   /* auto по горизонталі центрує блок */
}

Flexbox: розкладка в один ряд

Flexbox — інструмент для розташування елементів уздовж однієї осі: у рядок або в колонку. Батько отримує display:flex і стає «командиром», діти шикуються. Це як полиця: речі стоять в ряд, а ви керуєте, чи притиснуті вони до лівого краю, розтягнуті чи рівномірно розсунуті.

.toolbar {
  display: flex;
  justify-content: space-between; /* розсунути по головній осі */
  align-items: center;            /* вирівняти по поперечній осі */
  gap: 12px;                      /* відстань між дітьми */
}
.toolbar .search { flex: 1; }     /* забрати весь вільний простір */

/* Grid: класична сторінка з шапкою, бічною панеллю і підвалом */
.page {
  display: grid;
  grid-template-columns: 240px 1fr;      /* дві колонки */
  grid-template-rows: auto 1fr auto;     /* три рядки */
  grid-template-areas:
    "header header"
    "sidebar main"
    "footer footer";
  min-height: 100vh;
  gap: 16px;
}
.page > header  { grid-area: header; }
.page > aside   { grid-area: sidebar; }
.page > main    { grid-area: main; }
.page > footer  { grid-area: footer; }

Адаптивність і медіазапити

Сайт відкривають з телефону (375px) і з монітора (2560px). Медіазапити (media queries) дозволяють змінювати стилі залежно від ширини екрана. Сучасний підхід — mobile-first: спочатку пишемо стилі для вузького екрана, потім додаємо правила для ширших:

/* базові стилі — для мобільного */
.page { grid-template-columns: 1fr; grid-template-areas: "header" "main" "sidebar" "footer"; }

/* від 900px — дві колонки */
@media (min-width: 900px) {
  .page {
    grid-template-columns: 240px 1fr;
    grid-template-areas: "header header" "sidebar main" "footer footer";
  }
}

Обов'язковий тег <meta name="viewport" content="width=device-width, initial-scale=1"> у <head> — без нього телефон покаже сторінку як зменшену версію десктопної, і медіазапити не спрацюють.

CSS-змінні

Користувацькі властивості (custom properties) — змінні прямо в CSS. Ідеально для тем і повторюваних значень:

:root {
  --color-primary: #1f6feb;
  --space: 16px;
  --radius: 12px;
}
.button { background: var(--color-primary); padding: var(--space); border-radius: var(--radius); }

/* темна тема: перевизначаємо тільки змінні */
@media (prefers-color-scheme: dark) {
  :root { --color-primary: #6ea8ff; }
}
Підводні камені
  • Забули box-sizing: border-box — і елемент шириною 100% + padding 16px вилазить за екран, з'являється горизонтальний скрол.
  • margin сусідніх блоків по вертикалі схлопується (margin collapsing): два відступи по 20px дають 20, а не 40. У flex/grid контейнерах цього не відбувається.
  • Селектор із трьома класами і id перебиває все — потім не зрозуміло, чому стиль «не застосовується». Тримайте специфічність низькою: один клас на правило.
  • height: 100% не працює, якщо у батька не задано висоту. Для повного екрана використовуйте min-height: 100vh або 100dvh.

4. JavaScript: мозок

Змінні і типи

У сучасному JS змінні оголошують через const (не можна переприсвоїти) і let (можна). var — застарілий, не використовуйте. За замовчуванням пишіть const, а let — лише коли справді треба міняти.

const name = "Мурчик";       // рядок (string)
let age = 3;                 // число (number) — і цілі, і дробові
const isHungry = true;       // логічний (boolean)
let owner = null;            // «навмисно порожньо»
let nickname;                // undefined — «ще не задано»
const big = 12345678901234567890n; // bigint
const id = Symbol("id");     // symbol — унікальний ключ

// об'єкт — набір пар ключ: значення (як картка в картотеці)
const cat = { name: "Мурчик", age: 3, tags: ["рудий", "ледачий"] };

// масив — впорядкований список
const cats = ["Мурчик", "Барсик", "Сімба"];

console.log(typeof name, typeof age, typeof cat, typeof cats);
// "string" "number" "object" "object"  (масив теж object!)
console.log(Array.isArray(cats)); // true

Функції і стрілки

// звичайна функція
function greet(who) {
  return `Привіт, ${who}!`;   // шаблонний рядок з підстановкою
}

// стрілкова функція — коротший запис
const greet2 = (who) => `Привіт, ${who}!`;

// параметри за замовчуванням
const greet3 = (who = "світе") => `Привіт, ${who}!`;

console.log(greet("Мурчику"), greet2("Барсику"), greet3());

Стрілкові функції не мають власного this — для звичайних колбеків це зручно, для методів об'єктів іноді ні. Поки що правило: колбеки і короткі функції — стрілки, «іменні» функції верхнього рівня — function.

Масиви і об'єкти: щоденна робота

const todos = [
  { id: 1, text: "Купити молоко", done: false },
  { id: 2, text: "Написати код", done: true },
  { id: 3, text: "Погуляти", done: false },
];

// map — перетворити кожен елемент, отримати новий масив
const texts = todos.map((t) => t.text);            // ["Купити молоко", ...]

// filter — відібрати ті, що підходять
const active = todos.filter((t) => !t.done);       // 2 елементи

// find — перший, що підходить (або undefined)
const second = todos.find((t) => t.id === 2);

// reduce — «згорнути» масив в одне значення
const doneCount = todos.reduce((sum, t) => sum + (t.done ? 1 : 0), 0); // 1

// деструктуризація — витягти поля в змінні
const { text, done } = todos[0];
const [first, ...rest] = todos;   // first = перший, rest = решта

// spread — розгорнути; створює НОВИЙ об'єкт/масив, не змінює старий
const updated = { ...todos[0], done: true };
const more = [...todos, { id: 4, text: "Спати", done: false }];

Зверніть увагу: map, filter, spread — усі повертають нові структури і не чіпають старі. Це називається імутабельність (immutability), і на ній тримаються React та інші фреймворки з розділу 08.

Асинхронність: async/await

JavaScript у браузері працює в одному потоці. Якщо запит до сервера триває 2 секунди, а ми його «чекаємо» звичайним способом — сторінка замерзне. Тому довгі операції асинхронні: ми кажемо «зроби це, а коли буде готово — поклич мене», і продовжуємо працювати. Це як замовити каву і сісти за столик, замість того щоб стояти біля бариста.

// Promise — «обіцянка» повернути результат потім
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

// async/await — синтаксис, щоб писати асинхронне як синхронне
async function main() {
  console.log("Замовив каву");
  await wait(2000);          // чекаємо, але сторінка НЕ замерзає
  console.log("Кава готова");
}
main();
console.log("Сів за столик"); // виведеться ДО «Кава готова»
Чому це важливо

Майже кожна дія frontend-розробника — асинхронна: запит до API, таймер, клік, анімація. Якщо не зрозуміти await і чергу подій зараз, то далі буде постійне «чому змінна undefined, я ж її щойно отримав із сервера?». Відповідь завжди одна: ви прочитали її раніше, ніж обіцянка виконалась.

5. DOM і події

Як ми бачили в розділі 01, браузер перетворює HTML на дерево — DOM (Document Object Model). JavaScript працює не з текстом HTML, а з цим деревом: шукає вузли, змінює їх, додає нові, слухає події.

// Знайти елементи
const title = document.querySelector("h1");           // перший h1
const items = document.querySelectorAll("#list li");  // усі li в #list (NodeList)
const btn = document.getElementById("add");

// Прочитати / змінити
title.textContent = "Новий заголовок";   // текст (безпечно)
title.classList.add("highlight");        // додати клас
title.style.color = "red";               // інлайн-стиль (краще через клас)
btn.disabled = true;                     // атрибут-властивість

// Створити і вставити
const li = document.createElement("li");
li.textContent = "Новий пункт";
document.getElementById("list").append(li);

// Видалити
li.remove();

Ніколи не вставляйте текст користувача через innerHTML — якщо він введе <script> або <img onerror=...>, ви отримаєте XSS (Cross-Site Scripting). textContent вставляє текст як текст, і теги не виконуються.

Події

Подія (event) — це сигнал: «клікнули», «ввели символ», «сторінка завантажилась», «прокрутили». Ми підписуємось на подію через addEventListener і передаємо функцію-обробник:

const form = document.querySelector("form");
const input = document.querySelector("#todo-input");

form.addEventListener("submit", (event) => {
  event.preventDefault();          // не перезавантажувати сторінку
  const text = input.value.trim(); // що ввів користувач
  if (!text) return;
  addTodo(text);
  input.value = "";
});

// Делегування: один слухач на список замість слухача на кожен li
document.querySelector("#list").addEventListener("click", (event) => {
  const li = event.target.closest("li"); // на якому li клікнули?
  if (!li) return;
  li.classList.toggle("done");
});

Події «спливають» (bubbling): клік по <li> спочатку спрацьовує на ньому, потім на <ul>, потім на <body>. Тому можна повісити один слухач на батька і ловити кліки всіх дітей, включно з тими, що з'являться пізніше. Це делегування подій (event delegation).

6. fetch: розмова з сервером

Усе, що ми досі робили, живе в браузері. Щоб отримати дані з сервера (розділ 01: запит → відповідь), використовують fetch. Він повертає Promise, тому працює з await. Головне правило: перевіряйте статус і ловіть помилки. fetch не кидає виняток на 404 чи 500 — тільки на мережеву помилку.

async function loadTodos() {
  try {
    const res = await fetch("https://jsonplaceholder.typicode.com/todos?_limit=5");

    if (!res.ok) {                      // ok = статус 200–299
      throw new Error(`HTTP ${res.status}`);
    }
    const todos = await res.json();     // тіло → JS-масив
    render(todos);
  } catch (err) {                       // мережа впала, JSON битий, або наш throw
    console.error("Не вдалося завантажити:", err);
    showError("Щось пішло не так. Спробуйте пізніше.");
  }
}

// Відправити дані (POST з JSON)
async function createTodo(text) {
  const res = await fetch("/api/todos", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ text, done: false }),
  });
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return res.json();                    // сервер зазвичай повертає створений об'єкт
}
Підводні камені
  • CORS. Якщо сторінка на localhost:5173 робить fetch до localhost:3000, браузер заблокує відповідь, поки сервер не надішле заголовок Access-Control-Allow-Origin. Це захист браузера, а не помилка вашого коду. Рішення — на сервері (розділ 04).
  • Забули await перед res.json() — отримали Promise замість даних.
  • Забули перевірити res.ok — сервер повернув 500 з HTML-сторінкою помилки, res.json() впав із «Unexpected token <».

7. localStorage: пам'ять браузера

localStorage — маленьке сховище «ключ → рядок» у браузері, яке переживає перезавантаження і закриття вкладки. Це шухляда для дрібниць: тема, чернетка, список справ без сервера. Обмеження ~5 МБ, тільки рядки (об'єкти серіалізуємо в JSON), і доступне будь-якому скрипту на цій сторінці — тому ніколи не кладіть туди токени й паролі.

const KEY = "todos";

function saveTodos(todos) {
  localStorage.setItem(KEY, JSON.stringify(todos)); // об'єкт → рядок
}

function loadTodos() {
  try {
    const raw = localStorage.getItem(KEY);           // рядок або null
    return raw ? JSON.parse(raw) : [];               // рядок → об'єкт
  } catch {
    return [];                                       // битий JSON або приватний режим
  }
}

localStorage.removeItem(KEY);  // видалити один ключ
localStorage.clear();          // очистити все для цього сайту

Є ще sessionStorage (те саме, але живе до закриття вкладки) і IndexedDB (справжня база даних у браузері для великих обсягів). Для старту вистачить localStorage.

8. Доступність і DevTools

Доступність (accessibility, a11y)

Приблизно 15% людей мають ті чи інші обмеження: слабкий зір, неможливість користуватись мишею, дальтонізм. Доступна сторінка працює для них — і, як бонус, для пошуковиків і для вас із зламаним тачпадом. Мінімум, який має бути завжди:

  • Семантичні теги замість div-супу (розділ 2).
  • alt у кожної змістовної картинки (порожній alt="" — у декоративної).
  • <label> у кожного поля форми.
  • Усе клікабельне — доступне з клавіатури (Tab, Enter). <button> і <a href> це вміють самі.
  • Видимий фокус: не пишіть outline: none без заміни.
  • Контраст тексту з фоном не менше 4.5:1 (перевірити можна в DevTools).
  • Атрибути ARIA — коли семантики не вистачає: aria-label="Закрити" для кнопки з однією іконкою, aria-live="polite" для області, що оновлюється.

app.js — мозок

// ---------- Стан ----------
const STORAGE_KEY = "todos:v1";

/** @type {{id:number, text:string, done:boolean}[]} */
let todos = load();

// ---------- Елементи ----------
const form = document.getElementById("todo-form");
const input = document.getElementById("todo-input");
const list = document.getElementById("todo-list");
const count = document.getElementById("count");

// ---------- Робота зі сховищем ----------
function load() {
  try {
    return JSON.parse(localStorage.getItem(STORAGE_KEY)) ?? [];
  } catch {
    return [];
  }
}
function save() {
  localStorage.setItem(STORAGE_KEY, JSON.stringify(todos));
}

// ---------- Зміна стану (завжди через нові масиви) ----------
function addTodo(text) {
  todos = [...todos, { id: Date.now(), text, done: false }];
  commit();
}
function toggleTodo(id) {
  todos = todos.map((t) => (t.id === id ? { ...t, done: !t.done } : t));
  commit();
}
function removeTodo(id) {
  todos = todos.filter((t) => t.id !== id);
  commit();
}
// одна точка: зберегти + перемалювати
function commit() {
  save();
  render();
}

// ---------- Рендер: стан → DOM ----------
function render() {
  list.replaceChildren(); // очистити список

  for (const todo of todos) {
    const li = document.createElement("li");
    li.dataset.id = todo.id;            // data-id="..." для делегування
    if (todo.done) li.classList.add("done");

    const checkbox = document.createElement("input");
    checkbox.type = "checkbox";
    checkbox.checked = todo.done;
    checkbox.setAttribute("aria-label", `Виконано: ${todo.text}`);

    const span = document.createElement("span");
    span.textContent = todo.text;       // textContent, НЕ innerHTML — захист від XSS

    const del = document.createElement("button");
    del.className = "del";
    del.textContent = "×";
    del.setAttribute("aria-label", `Видалити: ${todo.text}`);

    li.append(checkbox, span, del);
    list.append(li);
  }

  count.textContent = todos.filter((t) => !t.done).length;
}

// ---------- Події ----------
form.addEventListener("submit", (e) => {
  e.preventDefault();                   // не перезавантажувати сторінку
  const text = input.value.trim();
  if (!text) return;
  addTodo(text);
  input.value = "";
  input.focus();
});

// делегування: один слухач на весь список
list.addEventListener("click", (e) => {
  const li = e.target.closest("li");
  if (!li) return;
  const id = Number(li.dataset.id);

  if (e.target.matches("input[type=checkbox]")) toggleTodo(id);
  if (e.target.matches(".del")) removeTodo(id);
});

// ---------- Старт ----------
render();

Що тут важливо архітектурно, навіть у такому маленькому проєкті:

  • Один стан — одна функція рендеру. Ми ніколи не правимо DOM «точково». Змінили масив todos → викликали render() → DOM перебудувався зі стану. Це та сама ідея, на якій побудований React: UI = f(state).
  • Імутабельність. addTodo, toggleTodo, removeTodo створюють нові масиви, а не змінюють старий. Це робить код передбачуваним і полегшує «відкат» чи історію.
  • Делегування подій. Один addEventListener на <ul> замість трьох на кожен <li> — і працює для елементів, доданих пізніше.
  • Безпека. textContent замість innerHTML. Спробуйте додати справу <b>жирна</b> — теги покажуться як текст, а не спрацюють.
  • Доступність. Підписи для чекбоксів і кнопок, aria-live, видимий фокус.
Спробуй сам
  1. Створи теку, поклади туди три файли, відкрий index.html. Додай кілька справ, перезавантаж сторінку — вони мають лишитись.
  2. Відкрий DevTools → Application → Local Storage → подивись ключ todos:v1. Зміни значення вручну і перезавантаж.
  3. Додай кнопку «Очистити виконані». Підказка: todos = todos.filter(t => !t.done).
  4. Додай фільтр «усі / активні / виконані». Підказка: ще одна змінна стану filter, і render() показує тільки відповідні.
  5. Замість localStorage завантажуй початковий список через fetch("https://jsonplaceholder.typicode.com/todos?_limit=5"). Зверни увагу: поле там називається title, а не text — доведеться перетворити через map.
  6. Пройди застосунок тільки з клавіатури: Tab, Enter, пробіл. Усе працює?
Для просунутих

Наш render() щоразу перебудовує весь список. Для 10 справ це непомітно, для 10 000 — гальмуватиме, бо кожна перебудова викликає layout і paint для всього <ul> (розділ 01, схема 5). Фреймворки на кшталт React вирішують це через virtual DOM і порівняння (diffing): вони обчислюють мінімальний набір змін і торкаються тільки потрібних вузлів. Але принцип «стан → рендер» той самий. Спробуйте самі оптимізувати toggleTodo, щоб він міняв клас лише на одному <li>, — і ви відчуєте, чому фреймворки взагалі з'явились.

Перевір себе

Питання
1. За що відповідає кожна з трьох мов фронтенду?

HTML — структура і зміст (скелет), CSS — зовнішній вигляд і розкладка (одяг), JavaScript — поведінка та інтерактивність (мозок).

2. Чому <button> краще, ніж <div onclick>?

Кнопка отримує фокус із Tab, спрацьовує на Enter і пробіл, оголошується скрінрідером як кнопка, і має стани disabled — усе безкоштовно. Для div це треба дописувати вручну.

3. Що таке box-sizing: border-box і чому його вмикають глобально?

З border-box задана width включає padding і border, тому елемент шириною 100% з padding не вилазить за батька. Це передбачуваніша модель, ніж стандартна content-box.

4. Коли Flexbox, а коли Grid?

Flexbox — для розташування вздовж однієї осі (панель кнопок, картка з іконкою і текстом). Grid — для двовимірних макетів (сторінка з шапкою, бічною панеллю і підвалом, галерея).

5. Чому «Сів за столик» друкується раніше за «Кава готова»?

await передає керування назад; таймер чекає у Web API; його колбек потрапить у чергу і виконається тільки коли стек викликів спорожніє. Синхронний console.log після виклику main() виконується одразу.

6. Чим textContent відрізняється від innerHTML і чому це питання безпеки?

textContent вставляє рядок як текст; innerHTML парсить його як HTML. Якщо в innerHTML потрапить введення користувача з тегами, це XSS-уразливість.

7. Чому fetch не кидає помилку на статус 404?

З точки зору fetch запит успішно виконався — сервер відповів. Помилкою вважається тільки мережевий збій. Тому треба перевіряти res.ok і кидати помилку самому.

8. Що таке делегування подій?

Замість слухача на кожному дочірньому елементі вішаємо один на батька і завдяки спливанню (bubbling) визначаємо через event.target, де саме клікнули. Працює і для елементів, доданих пізніше.

Що запам'ятати

  • HTML — структура, CSS — вигляд, JS — поведінка; не змішуйте ролі.
  • Семантичні теги і label/alt — це доступність, SEO і чистий код одночасно.
  • Box model: content → padding → border → margin; вмикайте box-sizing: border-box для всіх.
  • Flexbox — одна вісь, Grid — дві; медіазапити + viewport meta = адаптивність; CSS-змінні для тем.
  • const за замовчуванням, let коли треба міняти, var ніколи.
  • map/filter/find/reduce + деструктуризація + spread — щоденні інструменти; повертайте нові структури, не мутуйте старі.
  • async/await і цикл подій: довге чекання не блокує сторінку, але результат приходить пізніше.
  • DOM — дерево; querySelector шукає, textContent змінює безпечно, addEventListener слухає, делегування економить слухачі.
  • fetch: перевіряйте res.ok, обгортайте в try/catch, пам'ятайте про CORS.
  • localStorage — для дрібниць, не для секретів; тільки рядки, тому JSON.stringify/parse.
  • Стан → render(): змінили дані — перемалювали UI. Так працюють і ваш todo, і React.
